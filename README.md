# alry

目的と最初に作る機能を整理するための開発リポジトリです。

> 現在は企画・準備段階です。以下の目的・機能はたたき台であり、製品仕様として確定していません。実行可能なアプリケーションはまだありません。

## 目的（案）

日々の活動で繰り返す「情報を整理する・記録する・振り返る」作業を、小さなツールで楽にすることを目指します。

最初に、次の一文を埋めて対象を絞ります。

**「［使う人］が［困っている場面］で、［できること］を使って［得られる成果］を実現する。」**

### 決めること

- 誰が使うか：自分専用／限られたメンバー／一般公開
- 何を解決するか：具体的な困りごとを1つ
- 何をもって成功とするか：例「1件の記録と確認が1分以内に終わる」
- 利用環境：ブラウザー／コマンドライン／その他
- 保存する情報と公開範囲

## 機能案

以下は比較のための候補です。すべてを実装する予定ではありません。

| 候補 | できること | 最小版の範囲 |
| --- | --- | --- |
| 活動ログ | 活動内容を記録し、振り返る | 日付・内容の追加と一覧表示 |
| アイデア管理 | 思いつきを残し、実行候補を整理する | タイトル・メモの追加と一覧表示 |
| 投稿準備 | SNS投稿の下書きを整理する | 本文の保存と一覧表示。外部投稿は対象外 |

**最初の実装候補：活動ログの「追加 → 保存 → 一覧で確認」。**
これは仮案です。目的を確定した段階で、他の候補への差し替えも可能です。

初期版では、ログイン、外部API連携、自動投稿、課金、複雑な分析は扱いません。必要性が分かってから検討します。

## 開発方針

1. 目的と利用者を決める。
2. 機能を1つ選び、完成条件を文章で決める。
3. 利用環境に合う言語・フレームワーク・保存方法を選ぶ。
4. 入力から保存・確認まで動く最小版を作る。
5. 実際に使い、困った点を次の変更にする。

- 小さな変更ごとにブランチとPull Requestを作成する。
- 仕様の未決事項と決定理由を文書に残す。
- 初期版は必要最小限の依存関係にする。
- 秘密情報、認証情報、個人情報や実際の投稿データをコミットしない。
- 検証は機能の完成条件に合わせる。

具体的な手順は [開発ガイド](CONTRIBUTING.md)、実装候補と判断項目は [開発計画](docs/PLAN.md) を参照してください。

## 最初に作るファイル構成

現段階で用意するファイル：

```text
alry/
├── README.md
├── CONTRIBUTING.md
├── .gitignore
└── docs/
    └── PLAN.md
```

技術選定後に追加する構成の目安：

| 場所 | 役割 | 追加するタイミング |
| --- | --- | --- |
| src/ | アプリケーション本体 | 最初の実装時 |
| tests/ | 保存・入力検証などのテスト | 検証方法を決めた時 |
| 実行・依存管理ファイル | 起動方法と依存関係 | 言語・実行環境の決定後 |
| .env.example | 必要な環境変数名の説明。実際の値は含めない | 環境変数が必要になった時 |

フレームワークが標準の構成を持つ場合は、その構成を優先します。空のディレクトリや不要な設定は先に作りません。
