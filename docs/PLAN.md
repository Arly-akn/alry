## 2. 最初の実装候補：活動ログ

### 仮の利用場面

利用者がその日の活動を1件記録し、あとで一覧から振り返る。

### 最小限のデータ

- ID：記録を一意に識別する値
- 日付：活動した日
- 内容：活動の説明

文字数上限、日付の入力規則、表示順は実装前に決めます。
保存方式は、ブラウザー内／ローカルファイル／サーバー側などを利用環境に応じて選びます。

### 完成条件

- [ ] 日付と内容を指定して記録を追加できる
- [ ] 空白のみの内容は保存されず、理由が分かる
- [ ] 保存した記録が一覧に表示される
- [ ] 再起動または再読み込み後も、選択した保存方式から記録を復元できる
- [ ] 保存に失敗した場合に成功表示を出さず、入力内容を失わずに再試行できる
- [ ] 記録が0件でも正常に利用できる
- [ ] 保存先、データが消える条件、削除方法をREADMEに記載する
- [ ] 起動方法と検証結果をREADME・Pull Requestに記載する

### 初期版の対象外

編集・検索・集計・共有・アカウント・クラウド同期・外部サービス連携。

## 3. 作業の順番

1. **目的の確定**：対象利用者、困りごと、成功条件を更新する。
2. **仕様の確定**：機能、入力規則、保存方式、表示順を決める。
3. **環境の準備**：採用技術の標準構成を作り、起動手順を記載する。
4. **最小版の実装**：追加、保存、一覧表示をつなぐ。
5. **検証と改善**：正常入力、空白入力、0件、復元、保存失敗を確認し、次の課題を選ぶ。

各段階の判断が済んでから次に進みます。日程は作業量が見えてから設定します。
